# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：app.askは講座の情報について知らないので、一般論を推測して話していたが、agentツールで用語集を検索して、基礎実装発展のどれかで完了するっていうことを、簡潔かつ丁寧に答えていた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：search_glossary({'query': 'LoRA'})と search_glossary({'query': 'QLoRA'})
- 1つの質問での LLM 呼び出し回数（`requests`）：2回
- 追加したツールと、docstring に書いた説明：make_quiz(lecture: int)を追加、指定された回の復習用の確認問題を求められたときに使い、指定した回の用語から問題と答えを1つ作ってJSON形式で返す記述した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：search_glossaryのdocstringを、用語を1つずつ検索する説明から、比較するときは複数の用語をまとめて検索する説明に変更した。同じ質問を `--trace` 付きで実行し、変更前後を比較した。
- 結果：変更前は LoRAと QLoRA を別々に検索してtool_calls=2だったが、変更後はquery=LoRA QLoRAで1回だけ検索し、tool_calls=1になった。requestsはどちらも2回で、回答内容にも大きな変化せず、テストも問題なく成功した。
- 気づき・疑問：docstringは人向けの説明というよりは、モデルがツールの使い方とか引数を決めるための説明であるので、よりこだわれば人間が分かりやすいことよりもモデルに分かりやすい説明とかを考えられるなと思った。ツール呼び出しが1回減りましたが、結局LLMの呼び出し回数は2回なので、まあ多少の短縮にはなるが、まあよりClaude Codeみたいなリッチなハーネスを組んでたら、なんか抜本的な改革とかができるんだろうなと思った。
